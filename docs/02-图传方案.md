# 02 · 两种图传方案

赛题要求 1：车上装发送模块，车外装接收+显示存储装置，实时显示钢球画面并可录制回放。
本工程实现两套图传，按场地条件选用。

## 方案对照

| 项 | AP + MJPEG | RTSP (H.264) |
|----|------------|--------------|
| 脚本 | `gangqiujiance_ap_mjpeg_v*` | `gangqiujiance_v54_rtsp` |
| 网络模式 | 自建热点（AP） | 加入现有 WiFi（STA） |
| 视频编码 | JPEG 逐帧（multipart MJPEG） | H.264（VENC 硬编码） |
| 分辨率/帧率 | 320×180 @ 8fps | 1280×720 @ 512kbps |
| 观看方式 | 浏览器开 URL | VLC 等播放器开 RTSP 地址 |
| 延迟 | 中（JPEG 编码+8fps） | 低（硬编） |
| 依赖 | 无需路由器 | 需现场有可连的 WiFi |
| 录制 | 浏览器端/录屏软件 | VLC 可直接录制 |

## 方案 A：AP + MJPEG（默认推荐）

1. 上电后 K230 自建热点：
   - 亚博：SSID `FJPITYBK2301`，密码 `znzznb666`
   - 庐山派：SSID `FJPITLSPK230`，密码 `znzznb666lsp`
2. 手机/笔记本连接热点。
3. 浏览器打开 `http://192.168.4.1:80/` 看实时画面。
4. LCD 屏上也会显示该 URL。

优点：现场零配置，不依赖外部网络。适合赛场封闭环境。
代价：分辨率低（320×180）、8fps，够用但观感一般。

### 配置项

| 键 | 默认 | 说明 |
|----|------|------|
| `ap_ssid` / `ap_password` | 见上 | 热点名/密码 |
| `mjpeg_size` | `[320, 180]` | 流分辨率 |
| `mjpeg_fps` | `8` | 流帧率 |
| `mjpeg_quality` | `20` | JPEG 质量（1–100） |
| `mjpeg_port` | `80` | HTTP 端口 |

## 方案 B：RTSP

1. 改 `CONFIG["wifi_ssid"]` / `wifi_password` 为现场 WiFi（默认 `Xiaomi 15`）。
2. 上电后板子 DHCP 拿到 IP，LCD 显示 RTSP 地址。
3. VLC：媒体 → 打开网络串流 → `rtsp://<板子IP>:8554/ball`。
4. VLC「转换/保存」即可直接录制视频——满足赛题「完整记录并可回放」。

优点：720p 硬编高清、延迟低、可直接录制。适合需要高质量存档的场合。
代价：需要现场 WiFi（可用手机热点当路由器）。

### 配置项

| 键 | 默认 | 说明 |
|----|------|------|
| `wifi_ssid` / `wifi_password` | `Xiaomi 15` / `11234567` | 要连的热点 |
| `rtsp_size` | `[1280, 720]` | 流分辨率 |
| `rtsp_bitrate_kbps` | `512` | 码率 |

> RTSP 路径（CAM0→VENC 几何与编解码参数）沿用官方已验证例程，请勿随意改
> `rtsp_size` 之外的编码参数，容易推流失败。

## 怎么选

| 场景 | 选 |
|------|----|
| 赛场没网、求稳 | AP + MJPEG |
| 要高清录像/回放存档 | RTSP |
| 评委观看 + 自己留档 | AP 给评委手机看，RTSP 同时录（二选一部署） |

## 与 AI 检测的关系

两套图传只是「视频出口」不同，**AI 检测与串口发坐标完全一致**：
Sensor 三通道 → CHN_0 显示 / CHN_1 图传 / CHN_2 推理（224×224，~12ms/帧）。
切换方案不影响 MCU 收到的坐标帧。
